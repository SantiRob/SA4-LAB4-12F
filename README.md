# Express Health Service

A modular, production-ready Node.js service built with Express, structured according to Twelve-Factor App methodologies and configured for seamless deployment to Vercel.

---

## Quick Start

### 1. Install Dependencies
```bash
npm install
```

### 2. Configure Environment
Create a `.env` file from the provided example:
```bash
# macOS / Linux
cp .env.example .env

# Windows PowerShell
Copy-Item .env.example .env
```

### 3. Run the Service
- **Production mode:**
  ```bash
  npm start
  ```
- **Development mode (auto-reload):**
  ```bash
  npm run dev
  ```
- **Check versions (one-off admin script):**
  ```bash
  npm run info
  ```

### 4. Test `/health` with curl
Once the server is running, execute:
```bash
curl http://localhost:3000/health
```

Expected JSON response:
```json
{"status":"ok"}
```

## Environment Variables

| Variable | Default Value | Description |
| :--- | :--- | :--- |
| `PORT` | `3000` | Network port on which the HTTP server listens. |
| `NODE_ENV` | `development` | Execution environment (e.g. `development`, `production`, `test`). |

Configuration is loaded at startup using `dotenv` in [`src/config/index.js`](./src/config/index.js). The `.env` file is excluded from version control via `.gitignore`.

## Twelve-Factor App Alignment

This project implements the [Twelve-Factor App](https://12factor.net/) principles:

| Principle | Implementation in this Project |
| :--- | :--- |
| **I. Codebase** | Single codebase tracked in version control, deployable across multiple environments (local development, test, and Vercel production). |
| **II. Dependencies** | All dependencies (`express`, `dotenv`) are explicitly declared and locked in [`package.json`](./package.json) and `package-lock.json`. |
| **III. Config** | Configuration (`PORT`, `NODE_ENV`) is read directly from environment variables. A template is provided in [`.env.example`](./.env.example), and secrets/local `.env` files are ignored in [`.gitignore`](./.gitignore). |
| **VI. Processes** | The application is completely stateless with shared-nothing architecture, allowing multiple instances or serverless workers to run concurrently without side-effects. |
| **VII. Port Binding** | The application is self-contained and exports HTTP service directly by binding to the port provided by `PORT` (or default 3000). |
| **IX. Disposability** | Fast startup and graceful shutdown: intercepts `SIGTERM` and `SIGINT` to close open sockets before exiting, and immediately terminates on `uncaughtException` and `unhandledRejection`. |
| **XI. Logs** | Logs are treated as an unbuffered event stream written strictly to `stdout` via [`src/middlewares/logger.js`](./src/middlewares/logger.js); the app never manages log files or destinations. |
| **XII. Admin Processes** | One-off administrative and inspection tasks are executed as standalone scripts in the same environment (e.g. `npm run info` via [`scripts/print-info.js`](./scripts/print-info.js)). |

## Deploy to Vercel

The application is pre-configured for Vercel Serverless Functions:

1. **[`api/index.js`](./api/index.js)**: Serverless handler exporting the Express `app` without initiating a port listener.
2. **[`vercel.json`](./vercel.json)**: Rewrites all incoming paths to `/api/index.js`.
3. **[`.gitignore`](./.gitignore)**: Excludes `.vercel` metadata generated by the Vercel CLI.

### Deployment Commands
```bash
# Deploy to preview
npx vercel

# Deploy to production
npx vercel --prod
```
